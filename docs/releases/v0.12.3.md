# JAgentDesk v0.12.3

A bell with a notification list that every device shares, background task output you can actually follow, a resizable
inspector that keeps browser pages alive when you move them, no more identity leak through favicons, phone fixes for the
Memory screen and the background work sheet, push notifications that stop failing as a batch, steadier chat (compaction
rows, re-grounding sheet, bot item notes), bot worker fixes, and Paseo 0.18.1.

## Highlights

### Notifications: a list behind the bell

- The bell in the sidebar's host row now has an unread count and opens the host's notification list (a page on phones):
  agents that finished, asked for permission or failed, bots that need you or couldn't finish, and plugin notifications.
- The daemon keeps the list (500 items or 30 days) so the desktop and the phone see the same list and the same read state;
  opening an agent marks its items read everywhere. "Mark all read" and a shortcut to the notification settings are in the
  list.
- Notifications are set per device in Settings → This device → Notifications (from Paseo 0.18.0).

### Background tasks you can follow

- When a background command writes its output to a file (`> file`, `>> file`, `2> file`, `| tee file`), the task's details
  show that file as its own output tab, live. Only files in the agent's working folder or the system temp folder are read,
  never through a symlink outside them, and never secret files (`.env`, `.ssh`, keys).
- A command that runs a script (`zsh /tmp/wait.sh`, `bash x.sh`, `node x.js`, `./x.sh`) shows the script, so you can see what
  it waits for even when it prints nothing.
- When the agent reads that file (`cat`, `tail`, its read tool), the details show "Read by the agent" and what it read.
- The background work popover no longer opens by itself when you come back to an agent, on desktop or on phones.

### In-app browser

- **No more identity leak through favicons.** With the anti-detect profile on, the app's own favicon requests used to carry
  this computer's user agent and language. Favicons are now fetched through the tab with the tab's identity; checked with
  0 requests carrying the computer's identity.
- The right inspector is resizable (drag its edge, the width is remembered), a browser tab there has **Open in main pane**,
  and **Show** from the browser tabs list opens the tab in the main pane. Moving a tab between panes keeps the page, its
  state and its agent connection (no reload).
- An agent's new tab opens the inspector on that tab instead of on Files.
- The open browser tabs count moved next to the bell, with a pill above the composer for the tabs that agent opened.

### Chat

- A finished compaction shows one settled row, not a row that keeps spinning; the "Context compacted" and "Re-grounded"
  notices use the theme's colours.
- The "Re-grounded after compaction" and handoff sheets stay open and steady while the agent streams (they used to flicker
  and reload on every chunk).
- Bot item notes ("Moved …", "Commented on …") stay on one line and fold a run of changes to the same item into one row, as
  Orca does.

### Phones

- Pages under the phone top bar no longer draw a second title row and a large gap; the page's main action is the top bar's
  `+`. The Memory screen has padding, two filter rows and readable rows with their actions aligned.
- The background line under an agent's name in the drawer no longer opens the Background work sheet when you tap the row.
- **Workspace agents** button on a bot worker's workspace shows the Supervisor (the bot chat that started the worker), Lead
  and Peers.

### Bots

- A bot keeps its Home Chat and workers in its tree after a daemon restart, and its workers' repos no longer show up as
  empty projects.

### Push notifications

- A host that kept push tokens from older app builds could have every push rejected by Expo (one request mixing two Expo
  projects). Pushes are now split per project, malformed tokens are dropped, and Expo's error codes are logged (tokens
  never are). Android pushes are sent at high priority so they arrive during Doze (Paseo #8501).

### From Paseo 0.18.1

- Pi queues a prompt while it runs a turn it started itself; OpenCode v2 clears approvals OpenCode dropped and unloads an
  idle chat while another session runs; an ACP agent whose process exited while idle reopens.
- GitLab merge requests from forks load their pipeline jobs from the pipeline's project.
- Usage: Kimi global logins, the GLM Agent login, and enterprise spending for Claude and Codex.
- Host-wide instructions for commit messages and pull request text (Settings → Host → Workspaces → Metadata generation).
  Workspace titles and branch names stay algorithmic — no model is called for them.
- Command Center keeps its result order while you type; the New Workspace ref picker opens without a stutter (and its
  existing-worktree and Branch off / Check out actions are back); composer autocomplete reappears after closing overlays and
  hides while submitting; the iOS status bar no longer covers wide browser layouts or the Mermaid viewer.

## Breaking changes / action needed

- None. Apps and daemons from v0.11.x and v0.12.x work together; the notification list, per-device notification settings,
  background output files and the browser tabs list need both sides on v0.12.3.

## Upgrade notes

- Push notifications on phones also need the build to be able to receive them: the Android APK built by CI has no Firebase
  configuration (`google-services.json`), so it cannot get a push token; an unsigned iOS IPA gets push only if the tool that
  signs it adds the push entitlement (a free Apple ID cannot). See `docs/notifications.md` → "Expo push sending".
