# JAgentDesk v0.12.2

Stops the desktop app from crashing when an in-app browser tab or the window's renderer goes away under load, shows every
in-app browser tab that runs in the background next to the notifications bell and above the agent's composer, moves bot automations onto the shared Schedules list, fixes bot first-run,
Telegram linking and bot cards, tidies the composer trackers and the sidebar Usage summary, and brings in Paseo 0.18.0.

## Highlights

### The desktop app no longer quits when a browser tab or its window renderer dies

The desktop app could close itself without warning, most often while the machine was busy. The causes, all reproduced and
fixed:

- **A browser tab torn down while its identity was being applied.** The agentic browser applies the anti-detect identity
  (user agent, client hints, time zone, locale) to a tab before its first request. If the tab went away mid-way, code kept
  calling into it and the main process stopped. Calls into a tab now stop as soon as the tab is gone.
- **A browser tab that never got a renderer.** A tab that is not the visible tab of its pane (and every tab an agent opens
  in the background) waited for a renderer that never started, so its identity apply hung, the tab never loaded, and the hang
  ended in the crash above. Every held tab now gets a renderer from a blank page — no request leaves the tab — then loads
  with its identity.
- **A tab restarted under heavy load.** When a tab's renderer was killed while its identity was being applied, the blank
  page that restarts it could fail to load and the tab stayed blank. It is now retried.
- **Reloading a dead window too early.** When the window's renderer was killed, the app reloaded it from inside the exit
  event, which stops the main process. The reload now waits for the next turn of the event loop.

The identity apply has a 10-second limit. Past it the tab shows "Not responding" in the browser tabs list and its page stays
held until the identity is in place (with an anti-detect profile active, a page never loads without its identity).

### See every in-app browser tab, even the ones in the background

- **Next to the notifications bell** a globe button with a count appears whenever an in-app browser tab is alive, including
  tabs an agent opened in a workspace you are not looking at. The count turns amber or red when a tab is not responding or
  has crashed. Click it for the list: page title, `host · workspace · agent`, a status chip (Loading, Not responding,
  Crashed), **Show** (go to the tab) and **Close**, plus **Close all**.
- **Above the composer**, an agent that opened browser tabs has a globe pill with their count; it lists only that agent's
  tabs.
- A background tab that belongs to no workspace is listed as "Not in a workspace"; Show gives it a tab.
- Closing a browser tab no longer leaves an empty profile folder behind. On start the app removes such empty folders; it never
  touches the shared browser profile (your logins) or any folder that holds cookies or site data.

### Bot automations live on the Schedules list

- A bot's automations are now regular JAgentDesk schedules that belong to the bot. The Schedules screen lists them with the
  bot's mascot and where each runs ("Release readiness · Home Chat"), with a filter by bot; "Open on Automations page" in the
  bot panel opens Schedules filtered to that bot.
- Runs still land in the bot's Home Chat (or a given chat, or a new conversation), with its permissions and quiet replies.
  While the bot is paused its runs are skipped and shown as such.
- Automations are still created and changed by talking to the bot; on Schedules a bot's automation offers "Edit in
  {bot}'s chat", which opens the chat with a draft.
- Existing bot automations move over on the first start, keeping their id, cron, prompt, on/off and next run.

### Bots

- **First message no longer spins forever** after creating a bot: the first-run screen leaves as soon as the bot speaks. If
  setting up fails you see "Couldn't finish setting up" with **Try again**. The setup message is no longer shown as your own
  message.
- **Telegram linking**: "Link my Telegram account" opens Telegram with the code ready (`/start <code>`), the dialog turns into
  **Linked** by itself, and until an owner is linked the bot answers with how to link instead of staying silent.
- **Clearer cards**: approving a worker reads "Start a worker for #N …?" with the project, worktree and task; Needs you shows
  the tool by name ("Start worker"); one item asks once per worker start; workers, PRs and files are named in item activity
  instead of ids; the bot's own tool calls in its chat have readable labels.

### Composer and sidebar

- Subagents pill: failed children are listed first and each says how it ended (Failed, Stopped). The "1 failed" count was
  right: one subagent had ended with a provider "Overloaded" error.
- Background work list: one-line status rows and **Dismiss all**; the command block in a task's detail no longer keeps
  collapsing and expanding on phones.
- The sidebar **Usage** summary comes back after the app reloads its window (for example after running out of memory), has
  even space above and below instead of pressing on the Connection card, and shows each provider's own icon instead of a
  gauge when the host does not send one.

- **Send button like Paseo 0.18.0**: it appears only when there is something to send (text or an attachment); with an
  empty composer the voice-mode button takes its place, or nothing. It is the same size as the buttons next to it (28 px on
  desktop, 36 px on phones). While an agent runs, "Send and steer" is now labelled.

### From Paseo 0.18.0

- Syntax highlighting for diffs and patches, in chat and in the file viewer.
- **Per-device notification settings** (Settings → This device → Notifications) on every platform, with a switch per event
  and per plugin, and a notification API for plugins. Removing a host stops its notifications to this device.
- Agent profiles can set a **system prompt**; it adds to JAgentDesk's own instructions.
- OpenCode turns stop reliably after missed events and long histories.
- Pi: steering a run Pi started by itself continues it instead of aborting.
- Checking out a pull request fetches from the remote of the repository it belongs to (forks, GitHub Enterprise).
- ACP providers are probed less often and cached; Antigravity offers each model its own thinking levels and finishes turns
  after recurring schedules.
- Dropping attachments focuses the composer; client plugins that import `react-native` no longer crash iOS.

## Breaking changes / action needed

- None. Install v0.12.2 on desktop and phone. Apps and daemons from v0.11.x and v0.12.x work together; bot automations on the
  Schedules screen, per-device notification settings and the browser tabs list need both sides on v0.12.2.
- An app older than v0.12.2 no longer sees a bot's automations on the old bot record after the daemon moves them; update the
  app.

## Known limits

- Not ported from Paseo 0.18.0: browser tabs of a remote workspace going through that workspace's daemon (#10944). It would
  route those tabs around the anti-detect profile's proxy and split browser logins per host; it needs a decision first.
- Event automations (GitHub, GitLab, Telegram triggers) are not on the Schedules screen; they have no timetable. They still
  run through the bot's Home Chat.
- The crash fixes were checked on macOS (real app, anti-detect profile on, up to load average 90); not on Windows or Linux.
- After the window reloads, only the selected browser tab of each pane comes back live; the others reload when you select
  them, so the count drops until then.
- At extreme machine load an agent's `browser_new_tab` can time out while registering the tab; the agent is told to retry
  and the page still loads.
- Everything listed under Known limits in v0.12.0 still applies (bot sharing needs the relay's R2 bucket; real GitHub,
  GitLab, Slack and Telegram accounts not tested; Codex background tasks show no output).
