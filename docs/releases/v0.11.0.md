# JAgentDesk v0.11.0

Agents that keep their context. Switch an agent between Claude, Codex, OpenCode and other providers without losing what it
knows; fail over automatically when a provider hits its usage limit; give agents a memory you can read and edit; and keep long
agents sharp after compaction. This release also fixes phone pairing over the relay, JAgentDesk tools disappearing mid-session,
the browser agent opening your real browser, a background-process build-up that slowed the computer, and slow opening of long
agents.

## Highlights

### Switch providers mid-conversation, with context

- Pick a model from another provider in the composer's model menu: the same agent continues on the new provider.
- The new provider receives a structured handoff instead of a pasted transcript: your goals and constraints word for word, the
  decisions and open items, the files the agent read and changed (with diffs), commands and errors, and the last three turns —
  fitted to 60 % of the new model's context window.
- Switching back to a provider the agent used before resumes that provider's own session and sends only what changed since.
- A **Ledger** tab in the inspector shows this session ledger; every switch adds a "Switched to …" row with "View handoff".

### Failover when a provider runs out

- Settings → host → Agents → **Failover**: turn it on and order the providers to fall back to (per-agent override in the agent's
  ⋯ menu). When a provider reports a usage limit, the agent switches in place and re-sends the same message. Network and auth
  errors never trigger failover. At most one failover per turn and three per hour.
- With failover off, the usage-limit card offers **Continue with …**.
- **Push notifications** for a failover, for an agent stopped by a usage limit, and when no provider is left.

### Child agents on other providers

- Settings → host → Agents → **Child agents on other providers**: allow agents to start helpers on providers/models you list.
  Agents see each provider's remaining quota and are steered to the one with the most left.

### Memory

- A **Memory** page (sidebar) with Project and Global memories: what your agents learned about your projects and about you. Search,
  edit, pin and delete.
- Agents save with a `remember` tool (shown in the chat as "Remembered · …" with Undo/Edit); you can save any message with
  **Remember this**. Secrets are refused.
- Relevant memories are added to each turn automatically (local full-text search, no extra model calls) and the turn shows
  **Used N memories** — tap it to see exactly which ones.
- Works with every provider (checked with Claude, Codex, OpenCode and a custom OpenAI-compatible provider).

### Agents stay sharp after compaction and learn over time

- After every compaction (Claude, Codex and OpenCode signal it; other providers are detected from the token drop) the next turn
  re-grounds the agent: goals, decisions, open items, next step, the files it touched, commands and errors, and relevant lessons.
- A one-line "Goal · Next · Open" reminder on each turn; at 80 % of the context window the agent is asked to update its ledger
  before the provider compacts.
- **Lessons**: when you correct an agent it saves a lesson with a citation (file/excerpt). Lessons are checked against the files
  before use, expire after 28 days without use, and can be rated 👍/👎. Lessons that keep helping can become rules in
  `AGENTS.md`/`CLAUDE.md` — only after you approve the diff.
- **Rollover** (fresh session with a handoff) and **Capture lessons** are buttons in the agent's ⋯ menu; neither runs on its own.

### Faster forks

- Forking uses the provider's own fork where it exists (Claude), keeping the full context instead of a 100 KB summary. In tests a
  fork of a 303k-token Claude session appeared in 0.25 s. Forking never archives the source agent or workspace.

## Fixes

- **Phone pairing over the relay**: the desktop's Pair a device panel no longer replaces the QR code when the app's connection
  changes; a device that was already paired re-pairs instead of failing with "Device already paired"; the iPhone app loads its
  device key before signing (it could sign with an empty key and time out); each failure now says why. The relay Worker answers
  close frames and logs far less (Cloudflare observability quota).
- **JAgentDesk tools mid-session**: tools are recomputed every turn, so turning on Browser tools or a plugin applies to running
  agents; agents ask "Turn on … for this host?" instead of telling you to start a new session; tools come back after a daemon
  restart, an idle release, an OpenCode server restart, or a newer MCP protocol header — for every provider.
- **Browser agent**: browsing stays in JAgentDesk's browser; the providers' own browser tools (Codex's bundled browser plugin,
  Claude in Chrome) are turned off in JAgentDesk sessions, and the agent's tab opens selected in the inspector.
- **Jira**: agents use JAgentDesk's `jira_*` tools; the provider's own Atlassian connectors are hidden from agents (setting).
  Pasting a Jira link or typing an issue key adds an `#ABC-123` chip.
- **Machine slowdown**: replaced provider clients are retired (OpenCode's helper server stops), concurrent Claude model discovery
  is shared, and saving or deleting a custom provider refreshes only that provider — no more piles of `opencode serve`/`claude`
  processes. `docker events` watchers no longer leak (from v0.10.1).
- **Opening long agents**: the daemon keeps a snapshot of each agent's timeline and the app loads one tail page, so reopening a
  long agent takes well under a second after the first open (Claude 0.24–0.39 s, OpenCode 0.4–0.5 s, Codex 0.9–1.4 s in tests).
- **Archive shortcut** (⌘⇧⌫) no longer fires while typing; archiving by shortcut shows Undo for 8 s.
- **Background tasks**: shown as a compact track above the composer, with start/finish rows in the chat and a line under the
  agent in Recents — for every provider.
- **Settings**: every page has its own description, a divider under the title when scrolled, and empty states inside their card;
  **Pair device** lists paired devices with Revoke and search.

## Breaking changes / action needed

- No protocol break: apps and daemons of v0.10.x and v0.11.0 work together; new features turn on when both sides are v0.11.0.
- iPhone users: install the v0.11.0 IPA (pairing and relay sign-in fixes are in the app).
- The relay Worker was redeployed; nothing to do on your side.

## Upgrade notes

- The first time you open each long agent after updating, the daemon builds its timeline snapshot once; later opens are fast.
- Memory, Failover and Child agents on other providers start off or empty; turn them on in Settings → host.
- Lessons and project rules only change `AGENTS.md`/`CLAUDE.md` after you approve the diff.

## Known limits

- Native fork is used for Claude; Codex and OpenCode forks use the structured handoff.
- The `#ABC-123` Jira chip sits in the attachment row; the typed text stays in the box.
- Some checks were done on the web build rather than the Electron desktop app or a real phone; the iPhone relay sign-in fix is
  verified with the device after this release.
